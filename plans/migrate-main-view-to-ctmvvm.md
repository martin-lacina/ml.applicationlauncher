# Migrate Main View to CommunityToolkit.Mvvm and Shared Models

## Goal
Replace Prism-based ProcessViewModelBase / ProcessGroupViewModel / ProcessViewModel with CT.Mvvm-based CommandGroupViewModel / CommandProcessViewModel, eliminating the dual-model hierarchy. Remove all ICommandFactory usage from ViewModels. Keep Prism only for DI container and shell bootstrap.

## Final Recap

All 7 phases of the main view CT.Mvvm migration are complete. The dual-ViewModel hierarchy (ProcessViewModelBase/ProcessGroupViewModel/ProcessViewModel alongside CommandGroupViewModel/CommandProcessViewModel) has been unified to a single hierarchy using only the CT.Mvvm-based Command types.

### Key changes:
1. LastExecutedTracker - new composition class for time tracking, shared by both ViewModels via public property
2. MainWindowViewModel - fully migrated from Prism (BindableBase + DelegateCommand) to CT.Mvvm (ObservableObject + [RelayCommand])
3. RunOnProcessGroups - simplified from generic Action pattern to direct LastExecutedTracker calls
4. XAML controls - all DataTemplates updated, ProcessView wrapper eliminated in favor of direct StartButtonControl
5. Deleted files - ProcessViewModelBase.cs, ProcessGroupViewModel.cs, ProcessViewModel.cs, ProcessView.xaml, ProcessView.xaml.cs

### What remains (deferred):
- ICommandFactory removal from ViewModels (requires DI layer changes)
- RefreshableCommandFactory still uses Prism DelegateCommand internally (service layer, not ViewModel)
- 4 pre-existing null-reference warnings in EditView.xaml.cs (unrelated to migration)
